architecture note · expands review items #1 and #4

Single Point of Control

Two review findings, looked at closely: nothing currently owns the turret's shared state, and its tuning constants live scattered across four files. Both are the same underlying problem wearing different clothes.

issue #1

No single owner for shared state

Today this isn't a bug — it's a coincidence that works. physics_loop() is the only thing that ever assigns pan_vel, tilt_vel, pan_angle, and tilt_angle while the turret is running. smooth_reset() touches the same variables, but only after physics_loop() has already exited on shutdown — sequential, never at the same instant.

v2.0 adds a second live writer: the tracking loop, turning vision's dx into a velocity nudge. Now it wants to touch pan_vel in the same tick the keyboard thread might also be pushing on it — say you tap a out of habit mid-track. Nothing in the code decides whose write should count that tick; whichever line happens to run last wins, silently, by code order rather than intent.

illustrative sketch, not final code

mode = "MANUAL"   # or "AUTO", flipped by a mode-toggle key

def control_step():
    if mode == "MANUAL":
        if keys["a"]: pan_vel += ACC
        if keys["d"]: pan_vel -= ACC
    elif mode == "AUTO":
        pan_vel += Kp * target_dx

    # control_step() is the ONLY place pan_vel is ever assigned.
    # Keyboard and vision each hand it a request; neither writes
    # pan_vel directly anymore.

issue #4

Config scattered across files

Servo channels, physics constants, and vision defaults are all typed as bare literals at their call sites, not named or centralized. The scatter already produced a real inconsistency: color_tracker.py requests the camera at fps=30, while vision_test.py and TurretVision's own default both use fps=60 — nothing flags that the two scripts disagree.

illustrative sketch, not final code

# config.py — physical wiring + tuned constants, single source of truth
PAN_CHANNEL, TILT_CHANNEL, FIRE_CHANNEL = 0, 1, 2

ACC, FRC, TIME_LOOP = 0.3, 0.90, 0.02
SERVO_EPS = 0.05

FIRE_MIN, FIRE_MAX, FIRE_STEP = 90.0, 150.0, 5.0

DEFAULT_WIDTH, DEFAULT_HEIGHT, DEFAULT_FPS = 640, 480, 30

Why it's worth doing before v2.0 specifically: if the fire servo's wiring ever moves to a different PCA9685 channel, today that means hunting down the literal 2 across calibrate(), _update_fire(), and anywhere else it's typed — and a typo like _write_servo(1, fire_angle) would silently fire the tilt servo instead, with no error raised. One named constant removes the hunt entirely.

Both fixes are the same idea: give every piece of state exactly one place that's allowed to change it — a mode-gated arbiter for behavior, a config.py for constants. Per NOTES.md, these are the two things worth doing as v1.x cleanup, before v2.0 adds a second concurrent writer that needs somewhere sane to plug in.
