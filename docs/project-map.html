project map · autonomous tracking robot

Signal & Servo

A pan-tilt turret that watches for a colored target through a Pi camera and, for now, moves by hand — keyboard on one side, vision on the other, not yet talking to each other. This page maps the hardware, the software, and the concepts behind both halves.

currently at v1.1 — see roadmap below

the rig

What it's built from

Two servos give the turret its pan/tilt axes; a third fires. A camera rides on the tilt axis. Everything is driven from a Raspberry Pi over I2C, through a PCA9685 PWM driver board.

behavior, right now

Control flow — v1.1

Manual control is fully wired: keyboard → set_key() → the mode-gated arbiter → servos. The autonomous path exists as a scaffold — set_target_error(), the AUTO branch, a KP constant — but nothing calls it yet. That gap is the entire v2.0 milestone.

vocabulary

Concepts, grouped

The same grouping as NOTES.md — this is the illustrated index; that file has the full explanation of each.

Control / physics

  • Euler integration: vel += acc, pos += vel
  • Friction/damping (FRC = 0.90) so motion settles
  • Fire sequence as an explicit state machine
  • Non-blocking request_fire()

Concurrency

  • Daemon threads for keyboard + camera capture
  • Producer/consumer with a lock in TurretVision
  • try/except/finally lifecycle in main.py

Vision

  • HSV thresholding — robust to lighting, unlike raw RGB
  • Erode/dilate to clean a noisy mask
  • Largest contour + radius filter to reject noise
  • Interactive HSV tuning via trackbars

Software hygiene — v1.1

  • Hardware mock pattern — runs with or without a Pi
  • Dirty-checking before I2C writes (SERVO_EPS)
  • config.py as single source of truth
  • Mediator/arbiter (_control_step()) resolves one writer
